# Admin statistics and header account menu

The administrator Dashboard and Incident summary share `IncidentAnalytics` and `StatisticsChart`. Submission-date counts are the UI default. Daily, weekly, monthly and yearly grouping, category filtering, date ranges and an explicit incident-date fallback option use Philippine dates. Presets cover this month's daily counts, this year's monthly counts and five yearly buckets. Category totals, selectable stacked bars and a collapsible reusable data table expose exact counts without relying on colour alone. The annual range is bounded to 20 calendar years; other groupings retain the 366-day limit. Empty buckets are included. Rejected and soft-deleted reports are excluded; unverified reports remain explicitly included.

`IncidentStatistics` performs SQL aggregation for all matching records, independent of paginated lists. The existing incident-date default for API callers is retained. The export route uses the same service and authorization, validates the same filters and limits generation to six requests per minute. Applied filters are retained separately in the client, so changing an unapplied input does not export a different report. Exports recompute current records within that range rather than promise a frozen database snapshot.

Downloads are real PDF, Word DOCX and Excel XLSX files. Each includes the aggregate chart, date range, grouping, date basis and category counts. Excel includes numeric cells, typed literal text, a frozen table header, filters and a category-totals worksheet. No individual report text, photos, contact details or coordinates are exported. Dompdf disables remote resources, JavaScript and PHP. Private random temporary files are removed after generation; responses use no-store. GD renders the embedded chart. PHPWord and PhpSpreadsheet generate Open XML documents; these are not HTML or CSV renamed with an office extension. Composer resolves against PHP 8.2 and the workstation uses PHP 8.5. Actual hosts must provide the locked platform requirements, including XML and ZIP, and run `composer install` after pulling.

The shared header's account icon opens Profile, Settings and Log out for authenticated users; guests receive Settings and Sign in. A visible header Sign in replaces the sidebar account block. The old header settings icon and sidebar Profile/Settings destinations are removed. Their guarded deep links remain supported. Settings still exposes accessibility and the guide to guests. Keyboard arrows, Home/End, Escape, outside dismissal and restored trigger focus are supported.

Notification rows match the rendered notification-dialog header height through ResizeObserver, including font-size and viewport changes. Reference/time metadata and one-line ellipsis previews remain bounded. Selecting a notification still loads its full report through the existing authorization checks. The dialog footer is absent when it has no action.

Verification covers Manila boundary dates, selected date basis, per-category daily/yearly totals, empty periods, existing monthly/weekly contracts, admin-only access, invalid/unbounded inputs, actual document signatures/Open XML content, embedded chart media, numeric/literal spreadsheet cells and temporary-file cleanup. Browser checks exercise both pages, filtered downloads, unapplied edits, keyboard account actions, guest accessibility, notification geometry at 100/200% and phone reflow. See `05-testing-and-validation.md` and `TASKS.md` for the recorded result. Local/CI verification is separate from hosting deployment, actual Microsoft Word/Excel application review and physical Android acceptance.
